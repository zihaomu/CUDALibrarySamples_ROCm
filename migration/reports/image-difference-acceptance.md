# 图像库合理差异复评

2026-11-11 用户补充要求：“我觉得合理的差异是可用接受的，你从这个角度判断一下”。据此，后续目标采用**完整样例的功能等价支持**，同时单独记录精确一致程度。符合已声明算法/输出策略且效果合格的实现，可以计入支持；不再把所有厂商输出的逐像素复刻作为统一前提。

本次是既有输出的重新评估，**没有新增原始样例资格**。完整原始入口、GPU 实现、文件/CLI/类型分支及必需用例仍需通过。原严格模式的失败记录保持原样。

## 当前差异的判断

| 情况 | 工程判断 | 下一步 |
| --- | --- | --- |
| NPP+ 局部 Canny CPU 模型与 native 的 3 个外圈像素差异 | **可以接受为明示的边界行为差异**；不继续把这 3 点逐像素复刻作为功能支持的阻塞 | 固定项目边界/连接算法，GPU 与该独立 CPU 定义逐值验收；跨 vendor 保留内部比较、逐点边界差异与边缘统计，完成真实调用入口 |
| rocJPEG baseline 输出与 Pillow 默认 RGB 的较大局部差异 | **当前 10 张的差异可以接受**；控制变量实验表明上采样设置解释了绝大部分差异 | 使用输出策略匹配的独立 CPU 参考，并保留两种策略的质量指标；无需为复刻 Pillow 默认策略而先重写硬件解码后处理 |
| Canny 其它假设中出现的数千个差异 | 不能直接套用上述 3 点结论；需要确定是错误还是明确的 Canny 算法变体 | 合法变体按其算法定义及效果重新验收，单独标记兼容范围；不声称 NPP mask 精确兼容 |
| progressive JPEG 解码返回错误、尚缺 JPEG2000 GPU/MQ/HT/NLT 分支 | 属于功能缺失，**不能用误差容忍解决** | 继续实现相应 GPU 路线和完整调用流程 |
| JPEG2000 可逆/无损重建中像素错误 | 与无损承诺冲突，**不接受** | 对转换后规定表示逐值/bits 检查；合法码流的字节编码可以不同 |

## 新增控制变量实验

[机器结果及原始实验入口](image-difference-assessment.json)记录了完整命令、CPU 程序/库/输入/输出哈希。复用已封存的同一份 rocJPEG GPU 输出；本次仅在 CPU 参考中改变 `do_fancy_upsampling`，IDCT 固定 `JDCT_ISLOW`。宿主 libjpeg-turbo 为 2.1.5，独立 Pillow 使用 3.1.2。CPU helper 在开启平滑上采样时，对全部 10 张的输出与 Pillow 默认 RGB 逐字节一致。

libjpeg 提供平滑与快速色度上采样设置；跨不同设置的 RGB 结果不宜套用统一的少量 LSB 判据。[官方 API 文档](https://github.com/libjpeg-turbo/libjpeg-turbo/blob/main/doc/libjpeg.txt)、[官方配置说明](https://www.libjpeg-turbo.org/About/Performance.)说明了对应选项。

关闭平滑上采样后，与原封存 GPU 输出的测量如下：

| --- | ---: | ---: | ---: | ---: | ---: |
| img1.jpg | 27 | 3 | 0.2551 | 60.00 | 0.999818 |
| img2.jpg | 16 | 3 | 0.2451 | 60.34 | 0.999753 |
| img3.jpg | 52 | 3 | 0.2219 | 61.21 | 0.999717 |
| img4.jpg | 46 | 3 | 0.1898 | 62.57 | 0.999814 |
| img5.jpg | 21 | 3 | 0.2413 | 60.48 | 0.999883 |
| img6.jpg | 27 | 3 | 0.4165 | 55.74 | 0.999768 |
| img7.jpg | 43 | 3 | 0.2154 | 61.47 | 0.999912 |

RMSE 按 0–255 通道值计，当前最坏值为 0.417。配置匹配后，绝对误差的第 99 百分位均≤2，最大误差均≤3。这些结果足以支持当前普通图像样例的功能等价判断。剩余 1–3 级误差处于少量量化/舍入差异的量级；其逐阶段来源尚未证明，不将该推断写成已确认的内部实现细节。

maxAbs、RMSE、PSNR 和分位数覆盖全部像素；SSIM 为原分辨率 11×11 高斯窗口、sigma=1.5、valid 区域的单尺度测量，RGB 按通道平均，并另记亮度 SSIM。定义参照[SSIM 原作者资料](https://www.cns.nyu.edu/~lcv/ssim/)。SSIM 不是这里采用的唯一判据。

这里确认的是**这 10 张、这些配置与输出之间的差异可接受**，不是对所有 JPEG 输入或统一误差门槛的批准。未来 profile 的误差预算需根据位深、输出策略和样例用途先固定，再在新增独立 corpus 上验证；不把本表最坏值直接当作通用阈值。

## Canny 影响核对

13 个 CPU 模型/native 对照共 518,248 像素，11 个输入精确一致。剩余 3 点全部在最外一像素边界带，内部差异为 0；native 共 6,322 个边缘像素，模型共 6,319 个。

| 输入 | 尺寸 H×W | 不同像素 | native/model 边缘点 | IoU/召回率 | 坐标 `[y,x]` |
| --- | --- | ---: | --- | ---: | --- |
| holdout-low-noise-c1 | 67×79 | 2 | 43/41 | 95.35% | `[58,0]`、`[66,47]` |
| border-check40519-c1 | 65×63 | 1 | 35/34 | 97.14% | `[63,62]` |

“只有 3 点”不能只靠全图比例判断；第一张的 2 点占 native 边缘数 4.65%。本次接受依据是：差异明确局限于外圈、已定位为弱边缘模型的边界行为，内部结果完全一致，且可以给出稳定、独立可计算的项目算法定义。后续仍需用边界直线、交叉、弱边缘、孔洞和稀疏图核对该定义；不允许任意忽略整个边界、漏记失败 case，或放过内部断边/合并。

这些数据比较的是**CPU 模型与 native**。最终 HIP mask 和三个完整 Canny 调用入口仍未交付，不把这次接受差异的判断冒充 GPU 整例通过。先前被独立 holdout 否定的 boundary-self 假设仍保持拒绝；项目算法的主参考并未改成该假设。

## 后续统一验收方式

使用现有 PASSED/PARTIAL/FAILED 状态，不另造相互冲突的通过总表。通过项额外记录 `comparison_mode`：

| 模式 | 判定内容 |
| --- | --- |
| `EXACT` | 同一确定性定义的像素/字段精确；无损/可逆数据与硬性元数据采用此类 |
| `NUMERICAL_TOLERANCE` | 处理参数一致，按预先固定的逐分量误差与质量指标验收；适用于浮点、IDCT/颜色舍入等 |
| `ALGORITHM_VARIANT` | 明示的合法边界、上采样或算法选择；主参考验证选定算法，跨 vendor 记录质量/结构差异及兼容范围 |

1. **完整功能优先**：整个原始样例与必需分支通过，`NUMERICAL_TOLERANCE` 或 `ALGORITHM_VARIANT` 同样可以计入支持；首页与算子表注明具体方式、效果和差异。
2. **结构性结果分开判断**：CCL 的 label 编号可在保持同一分区/背景/分量数的前提下重命名；不能用像素差异占比放过两个连通域被合并。Contour 起点/列表顺序差异需要保持几何及有语义的方向、孔洞和归属。算法本身改变分区时使用单独 profile 评估，不一概当作可忽略差异。
3. **执行与格式仍有硬约束**：尺寸、位深、通道顺序、ROI、padding、ABI、stream/batch 生命周期、完整文件输出和 GPU 实际执行必须正确。空输出、丢 batch/scan、模式缺失与整幅 CPU codec 回退不属于合理数值差异。
4. **预先定义并反向检查**：每个 profile 固定参考配置、允许差异范围、指标和恢复条件；新增独立输入及错通道、错 ROI、丢结果等反例必须能区分好坏实现。保留全部原始严格模式观测，不事后改写为通过。

支持计数仍为项目 **241/23/375**，图像范围 **2/8/16**；本次调整解除的是不必要的精确复刻要求，剩余入口/模式的实际实现和验收继续保留。
